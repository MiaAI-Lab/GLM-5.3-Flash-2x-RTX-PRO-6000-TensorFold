# Review: warm turns for GLM-5.3-Flash TP2

## Q1 — what GLM's CUDA family actually lacks

**1. No `warm_quiet` decl — confirmed, but the brief's fix implied by it is incomplete.**
`families/glm/cuda_native.zig` declares `snap_grid`, `snap_min_bytes`, `snap_ready`, `snap_host_tier`, `snap_charged`, `snap_spare`, `snap_reuses`, `snap_save/restore/drop` — and no `warm_quiet`. So `native/cuda.zig`'s Info literal (`.warm_turnes = h.store != null and @hasDecl(F, "warm_quiet")`, the line the brief cites as :483) evaluates false. The store itself exists (GLM has `snap_save` and a nonzero `kept_budget` via `snap_host_tier`), so `h.store != null` is satisfied. **But the brief misses the second hardcode:** `Host.serve` sets `h.host.warm_quiet = if (info.warm_turns) nemotron.native.warm_quiet else 0;` (the :133 line). `serve` is runtime, `F` is not in scope there. Adding the decl to GLM alone does nothing useful — it would silently serve nemotron's quiet constant. The value must be captured in `openWith` (comptime `F` in scope) into a new `Host` field.

**2. Yield plumbing is the real gap, not the decl.** `warmPass` (lane_host.zig) runs `be.prefill` synchronously on the engine thread, inside `launch` ← `admitOne` ← `run`. While it runs, nothing else is admitted, no `core.step`, no `fill.run`. The escape hatch is `error.Yielded` via the stream's `yield_check` (set in lane_stream.zig `open` for `background and max_tokens == 0`, pointing at `LaneHost.yieldsTo`). Nemotron plumbs this: `e.prefillFrom(..., .yields = s.yield_check != null, ...)` (nemotron/cuda_lanes.zig, the `prefillFrom` call in the attached excerpt). GLM's `prefillFn` (cuda_lanes.zig) passes only `.{ .ptr = s, .check = cancelled }` to `self.x.prefill(...)` — no yields hook. Unless `follow.Leader.prefill` (cuda_follow.zig, **not attached — verify**) accepts and honors a yield flag at chunk boundaries, a 100K-token warm pass blocks the engine thread for ~20–25 s at your measured 4–5K tok/s, and `warmPass`'s `error.Yielded` arm is dead code. Cancellation works today (the `cancelled` check fires between chunks, and GLM's `Marks.interrupted = keptInterrupted` hook exists), but *yield* is the mechanism by which a foreground arrival actually stops the pass — nobody cancels the warm job explicitly.

**3. TP2: no special broadcast needed — the brief's worry is unfounded.** Rank 0's `follow.Leader` drives the followers through the same link as any prompt pass; `readySnapshots` in cuda_native.zig already uses a throwaway `follow.Leader` + `x.idle()` to wake/re-sleep ranks, and `releaseFn` does `x.idle()` when the last lane leaves. A yield/cancel decision is made on rank 0 only; chunk boundaries are the natural sync points. One thing to verify: `pagesFor(slot, prompt, max_new=0)` — the warm pass has `max_tokens = 0`, and I can't confirm `pages.open` accepts a zero-length reply extension from the attached code. Check cuda_pages.zig before trusting it.

**4. Keeps: the marks path, not `keepBorn`.** GLM's rules via cuda_snaps.zig `cacheRules`: `snap_grid` set → `planned`, lookahead defaults to **1** (no `snap_lookahead` decl). So in `warmPass`, the trailing `store.keepBorn(...)` is gated on `store.rules.lookahead == 0` and **is skipped for GLM**. Keeps happen instead mid-prefill via `marksOf(s)` → `keptAt` → `Job.kept` at the store's grid marks — which is why kept states stop one chunk short of the end (your observed "last 1024-token chunk" exclusion). Also note the early-cancel in `warmPass`: `job.marks.len == 0 and lookahead > 0` → the pass is cancelled before running a single chunk if `lookupUser` returns no marks. For a 100K prompt on the `snap_grid` this should be fine, but it's the first thing to check in a replay after enabling. Side note: the brief says "prompt chunks of 4,096 rows", but `snap_grid = fw.prefill_rows` and your own keep-gap measurement says 1024 — one of those is wrong; check cuda_forward.zig.

**5. Pool pressure:** the warm pass seats prompt-sized pages (`opening` → `seat` → `pagesFor`) beside 4 live streams. Admission (`F.fits` → `p.fits`) holds new jobs while the pool is short (`admit.holds`); `warmPass` on `error.LaneMemory` drops (it doesn't use `failedPass`'s requeue arm) — noisy but safe. `fitsContext(prompt, 0, cap)` passes.

**6. Drafter:** untouched — DFlash2 only runs in decode (`draftBlock`), and the warm pass never decodes. `l.first = self.take(first)` and the ring are harmless.

## Q2 — is warm turns the right fix? Yes.

The token-level facts leave no room for a cleverer trick: the with-reasoning rendering (in-loop) and the cleared rendering (after the next user msg) diverge at the **first assistant turn after the old last-user index**, and KV is exact-token — the only reuse is the common prefix, which is exactly the `cached=4096/8192` you measure. You cannot splice (ruled out), and the template cannot be made position-stable without either keeping reasoning forever (`CLEAR_THINKING=0`, rejected) or clearing in-loop too (changes the maker's intended loop behavior). The warm pass is the only mechanism that materializes the cleared rendering's KV before it's needed, and `server/warm.zig` already renders exactly the right thing (conversation + reply-as-sent + dummy user, two spellings, common prefix). It fixes **both** re-reads: the loop-step one (states past the reply don't exist without it — kept states exclude the reply) and the next-user one (cleared re-render). Nothing to change in warm.zig.

## Q3 — minimal patch

1. `families/glm/cuda_native.zig`: `pub const warm_quiet: u64 = …;` (start at nemotron's value; it's "how long the engine must be idle before the pass commits" — too large and sub-second agent turns starve it out entirely, too small and it yields after one chunk; measure).
2. `native/cuda.zig`: add `warm_quiet_ns: u64 = 0` to `Host`; set it in `openWith` (`if (@hasDecl(F, "warm_quiet")) h.warm_quiet_ns = F.warm_quiet;`); change the `serve` line to `h.host.warm_quiet = h.warm_quiet_ns;`. This also fixes the latent wrong-value bug for every non-nemotron family.
3. `families/glm/cuda_lanes.zig` `prefillFn`: thread the yield check into `Leader.prefill` (mirror nemotron's `.yields = s.yield_check != null`), and confirm/extend `cuda_follow.zig` `Leader.prefill` to return `error.Yielded` at a chunk boundary after invoking `Marks.interrupted` — `warmPass` already treats `Yielded` as cancel-and-keep.
4. Test: extend `lane_host_warm_test.zig` with the GLM-shaped case — planned grid rules, `lookahead = 1`, `warm = .waits`, foreground arrival mid-pass → warm finishes `cancelled`, a follow-up request's `prefilled` cached equals the last kept mark, not 0. Plus a `cuda_follow`-level test for `Leader.prefill` yielding, if that plumbing is new.

**Risks:**
- Engine-thread stall: without (3), a 100K warm pass blocks admission/decode ~20 s; with (3), the granularity is one chunk (`prefill_rows`) — a ~0.2–1 s latency spike per yield, acceptable.
- Double prefill if the user replies mid-pass: bounded waste (work up to the last mark is kept), no correctness issue.
- Pool/snapshot pressure: warm-pass pages plus 4 streams' windows can hold admissions (`admit.holds`); mid-pass keeps evict other conversations' store entries — watch hit rate on the live server.
- `pages.open(..., max_new = 0)` and the `marks.len == 0` early-cancel are the two unverified paths — check both in the replay before declaring victory.
- Pre-existing, not yours: `warm.zig` `Pass.event` tears down the arena (request slices) from the sink callback while `finish` is still touching the job — it's tested, but don't add allocations from that request after `emit`.

**Recommendation:** do 1–3; it's ~20 lines plus the test. The template is a dead end; warm turns is the exact mechanism this tree already built and tested for the nemotron family, and GLM is missing only the decl, the per-family plumbing in cuda.zig, and the yield hook in its prefill.
