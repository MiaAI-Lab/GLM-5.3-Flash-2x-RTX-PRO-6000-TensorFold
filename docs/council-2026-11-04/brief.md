# Council brief: a follow-up user message re-reads the whole previous agent turn (GLM-5.3-Flash on TensorFold, 2x RTX PRO 6000, TP2)

## The problem, measured
Server: TensorFold native Zig engine (this tree, pinned f350cd3 + 93 recipe patches), GLM-5.3-Flash EXL3, two ranks (tensor parallel 2), 4 streams, 1M window, host-RAM prompt cache 8 GiB a rank (~8 MiB per 1K tokens, 13-15 kept states), prefill ~4-5K tok/s.
Chat template (GLM's own, `clear_thinking` on, TF_GLM_CLEAR_THINKING=1): an assistant turn's reasoning is rendered only for messages AFTER the last user message. During an agent tool loop the loop's assistant turns render WITH reasoning; when the next user message arrives they render with an empty `<think></think>`. So the rendered prompt changes at the first assistant turn after the previous user message and the prefix cache resumes there: the whole previous agent turn (tool calls + tool results, often 50-100K tokens) is prefilled again, 10-30 s before the first token.
Replay on the live server (small tool loop, reasoning on, client sends reasoning_content back like the pi agent does): next loop step prompt=9279 cached=4096; next user message prompt=9335 cached=4096 (the re-read); same with chat_template_kwargs clear_thinking=false: cached=8192; same with the client sending no reasoning_content: cached=8192. Kept states exclude the reply and the last 1024-token chunk.
Rejected so far: CLEAR_THINKING=0 (keeps all reasoning in context forever; prompts grow by the reasoning, against the model maker's default), a bigger cache (does not address this), thinking off.

## What the engine already has (verify, do not take on faith)
- zig/src/server/warm.zig: after a chat reply on a `warm_turns` engine, the server renders conversation + the reply as sent + a dummy user message (two spellings, common prefix), and submits a background prompt-only request (max_tokens 0, background=true) so the next turn resumes past the reply. Because the reply and the loop turns sit before the dummy user message, this rendering is the cleared one: exactly what the next real user message will send.
- zig/src/core/lane_host.zig: warmPass, startsAlone, setup (warm_quiet: a warm pass waits for other work before its first chunk; a yield ends it and what it prefilled is kept), lane_stream.zig yield_check.
- zig/src/native/cuda.zig:483: `.warm_turns = h.store != null and @hasDecl(F, "warm_quiet")` and :133 `h.host.warm_quiet = if (info.warm_turns) nemotron.native.warm_quiet else 0;` The GLM family (zig/src/families/glm/) apparently declares no warm_quiet, so warm turns are off for GLM; the rank log never mentions a warm pass.
